# Document task content previews

This policy applies to the plugin's uploaded task-event previews, including property
names, input values, tool output and error messages. It does not modify documents or
the original tool objects. Uploads are off unless `docTaskProgress` is explicitly
true for the account (or inherited from the channel). The target document's
readers can view uploaded previews; the filter does not grant or narrow their
server-side document permissions. This includes HTML tasks, whose receipt write
uses the source slug with the prepared task key; see the [receipt contract](ppt-contract.md#document-task-progress-receipts). See [upgrade instructions](../README.md#upgrading-to-document-task-receipts).

## Unicode normalization

Before detecting credentials, apply one policy to every string:

1. Remove Unicode `Cc` controls except TAB, LF and CR, which preserve ordinary layout.
2. Remove `Cf` format characters and `Default_Ignorable_Code_Point`. This includes
   zero-width joiners/spaces, soft hyphens, bidi controls, combining grapheme joiners,
   variation selectors, fillers and tag characters, including supplementary planes.
3. Remove `Zl` and `Zp` line/paragraph separators.
4. Normalize the remaining text to NFKC, folding compatibility forms such as
   full-width letters and punctuation. Removal precedes NFKC so invisible composition
   barriers cannot prevent canonically equivalent strings from converging.
5. Detect credentials on the exact normalized preview before its display-length cut.
   Use the same detector for keys and values. A sensitive key and its value both become
   fixed redaction markers. At the shared preview sink, recheck the separator-free
   concatenation of textual values in the sanitized object's/array's traversal
   order; keys are checked individually. For tool text blocks, check the selected
   text fragments and their displayed newline-joined form. This catches adjacent
   split credentials without treating JSON quotes, commas or display newlines as
   protection. Detection happens before display truncation and the combined text
   is bounded to 65536 characters; overflow withholds the preview. The policy does
   not search all field permutations or decode arbitrary encodings.

This deliberately normalizes the preview's typography and removes format controls;
ordinary visible letters, accents and TAB/LF/CR remain readable. It does not attempt
cross-script lookalike transliteration or identify all confidential business data.
The credential detector remains conservative and may hide benign hashes or prose.
PEM header matching bounds the label gap to 64 characters so repeated incomplete
`-----BEGIN ` markers cannot trigger quadratic scanning.
Schemeless userinfo (including localhost, IPv6 and passwords containing `/` or `@`)
and schemeless host/path text use the card renderer's exact shared matchers. The
upload replaces these private strings with redaction markers; it does not retain
credentials or paths that the card renderer would remove. The upload checks
whitespace-free tokens: userinfo candidates require both `:` and `@`, and
host/path candidates require `/`. Candidate tokens over 4000 characters cause
the whole preview string to be withheld, including any unexamined tail; shorter
candidates use the shared matchers. Long ordinary prose and dot-dense text with
no candidate markers avoid those backtracking matchers. Raw preview strings are
also subject to the 65536-character input budget before display truncation.

`doc-task-unicode.test.ts` enumerates 4270 codepoints from these classes (Unicode 17),
independently of the implementation's property regex. It checks neutral text and
34160 uploaded events generated by splitting credential keywords/prefixes and
interleaving property names across the complete corpus. Compatibility forms and
ordinary multilingual/layout controls are separate positive checks. When upgrading
Node/Unicode data, review additions to these classes and refresh the corpus.

## Reading objects

Before selecting output fields, copy only own enumerable data descriptors from
plain JSON records and arrays. Never invoke source getters, Proxy traps, array
methods or serialization hooks. Carry omission/redaction flags through extraction.
Non-sensitive normalized property names longer than 120 characters are shortened
and mark the preview `truncated`, just as omitted values do.
Exit metadata probes `exitCode`/`exit_code` in the root, `details`, `meta`,
`metadata` and `summary` records; the first signed 32-bit integer in that order
wins. These explicit exit fields apply to every tool, including custom tools;
they are status evidence, independent of the card renderer's display limits.
The ambiguous `code` alias is accepted only for exec/bash/shell/process tools.
Any readable `isError: true` in these records marks a failure. Native Error
messages use guarded descriptors too; display limits
do not erase otherwise valid exit status. Existing limits remain 4096 content
characters, 1000 events per attempt and batches of at most 10.

## Progress hook interaction

Card progress and document-task progress intentionally register against the same
OpenClaw API. The host's typed-hook registry appends registrations; its gate runner
executes higher-priority handlers first until a blocking decision (verified with
the installed OpenClaw 2026.8.1 runner). Both `before_agent_run` handlers return
`pass`; observational callbacks intentionally return nothing. Their session/run
ownership remains independent. The document observer also skips the same vetoed
tools as the policy gate, so it cannot record them if it runs before the veto.

The combined regression registers both modules in both orders and checks actual
card requests and document snapshots using separate IM/document session keys,
including the existing paused-card continuation on the IM key. Dropping either owner binding, dropping continuation
binding or replacing the append registry with a last-wins registry must fail.
Host hook implementation changes require rechecking these semantics; the regression
is a local component test, not a deployed OpenClaw/browser acceptance run.
